# Minecraft

Each game server gets its own name, `<server>.mc.<domain>`, and everything shares one port,
25565. Pelican runs the servers, mc-router sends each connection to the right one, and a sync
loop keeps the routes in step with Panel. Config: `modules/nixos/services/pelican/`, plus the
`minecraft` and `pelican` apps in `apps.nix`.

## The pieces

| Piece                  | Runs as                 | Job                                                            |
|------------------------|-------------------------|----------------------------------------------------------------|
| Pelican Panel          | k3s (`mc.<domain>`)     | Web UI and API. Creates servers, starts and stops them.        |
| MariaDB                | k3s                     | Panel database.                                                |
| Pelican Wings          | systemd (`pelican-wings`) | Runs each game server as a Docker container. Proxied at `wings.<domain>`. |
| mc-router              | systemd (`mc-router`)   | Listens on `:25565` and forwards by hostname.                  |
| pelican-mc-sync        | systemd                 | Keeps mc-router's routes in step with Panel. Wakes and stops servers. |

Docker game containers get their own address range, `172.30.0.0/16`, clear of k3s.

## Naming

A server named "Survival World" gets the label `survival-world`, so its address is
`survival-world.mc.<domain>`. Two servers with the same label use their identifier instead.
Blocky maps `mc.<domain>` to beacon's LAN address in `customDNS`. Subdomains of a mapped name resolve on
their own, so every `<label>.mc.<domain>` answers on the LAN. Outside the LAN, the Cloudflare wildcard
record sends them to beacon. Check after setup: `dig +short <label>.mc.<domain>` on a LAN client.
It should return beacon's LAN address.

## Routing

Every 15 seconds `pelican-mc-sync`:

1. Lists **all** servers from the Panel API (`/api/client?type=admin-all`), whatever their owner.
2. Reads each server's default port allocation.
3. Points `<label>.mc.<domain>` at the running server's port, or at a waker if it's stopped.
4. Removes routes for servers that no longer exist.

## Wake on join

A stopped server has a waker on `port + 100`, listening on localhost. When a player connects to it:

1. The waker asks Panel to start the server (at most once a minute per server).
2. It holds the connection for up to 3 minutes, until the server accepts connections.
3. It pipes the connection through to the real port.

## Idle stop

While a server runs, the sync checks its online player count every minute. When it has been empty
for 15 minutes, it asks Panel to stop it. Joins count as activity, so a server that's just been woken
isn't stopped straight away.

## Access

- The Panel is at `https://mc.<domain>`. The `minecraft` app is marked for Pocket ID, but the
  client is only used once `manifests/oidc/minecraft.sealed.yaml` exists. None is committed yet;
  see [pocket-id.md](pocket-id.md) to add one.
- Players connect to `<label>.mc.<domain>:25565`. Forward 25565 on the router for outside access.
- Minecraft's own admin console: `kubectl -n minecraft exec deploy/minecraft -- rcon-cli`
  (for the vanilla server in `manifests/minecraft.yaml`).

## First-time setup

1. Set up the Panel and the database. Secrets are generated by `secrets.sh` ([secrets.md](secrets.md)).
2. In the Panel, add beacon as a node and copy its Wings config into `/etc/pelican/config.yml`.
3. Start Wings: `sudo systemctl start pelican-wings`.
4. Create an admin API token and write it to `/var/lib/pelican/api-token`
   ([secrets.md](secrets.md#pelican-panel-api-token)). Then start the sync:
   `sudo systemctl start pelican-mc-sync`.
5. Create a server in the Panel. It appears under `<label>.mc.<domain>` within a minute.

`pelican-mc-sync` and `pelican-wings` don't start until their config files exist, so this order
is safe.
